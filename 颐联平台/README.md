# 颐联 · 多角色生活协同平台(静态演示)

面向居家养老场景的三端协同原型:**老人端**(自主安排生活)、**家属端**(在授权范围内协助)、**社区端**(服务调度)。三个角色各有独立界面与权限视角,通过同一件事在不同端之间的流转来演示"协同"。

---

## ⚠️ 先读这一段:这是一个纯演示页面

| 事项 | 现状 |
| --- | --- |
| 后端 / 接口 | **没有**。所有逻辑都在浏览器里,不发任何请求 |
| 数据存储 | 浏览器 `localStorage`(同源共享) |
| 账号 / 鉴权 | **没有**。三个角色不需要登录,直接点进各自入口 |
| 权限隔离 | **只是界面约定**。家属端的"只读"是样式,不是服务端校验 |
| 外部依赖 | 无。字体走系统字体栈,不加载任何 CDN |

因此页面上的「按需授权」「全程留痕」是**产品能力的示意**,不是已经实现的安全边界:

- 三个角色共用同一个 origin 的 `localStorage`,在开发者工具里改 `yilian-permissions` 就能绕过授权;
- `yilian-contact-requests` 之类的"留痕"是普通数组,可以随意改写,不构成审计证据。

**要做成真实系统,至少需要**:服务端鉴权、按角色的服务端权限校验、不可篡改的审计日志、数据加密与最小化下发。当前原型可以直接作为交互与信息结构的提案使用,但不能直接上线承载真实老人数据。

## 运行

不要直接双击 `index.html`(在 `file://` 下,`localStorage` 的分区规则和跨窗口 `storage` 事件的行为在不同浏览器里不一致,"三端同步"这条演示线会静默失灵)。用一个静态服务器:

```bash
python -m http.server 5182 --bind 127.0.0.1 -d .
```

然后打开 http://localhost:5182/ 。演示时建议**同时开三个标签页**(老人端 / 家属端 / 社区端),在老人端点"确认社区陪诊",切到另外两个标签页即可看到同步变化。

页脚有「重置演示数据」,清空本机保存的状态、回到初始场景。

## 页面结构

```
index.html            入口页(选择角色)
elder/                老人端
family/               家属端
community/            社区端
seed.js               演示种子数据(唯一的数据来源)
shared.js             三端共用的工具层:存储读写、日期、视图路由、抽屉、提示
role.css              样式表(按 @layer 分层,见下)
favicon.svg           站点图标
```

### 三端各自能做什么

- **老人端** `/elder/` — 查看今天最重要的事并**确认社区陪诊**;管理生活事项(新建/查看进度);主动联系支持者并接收回复;开关共享授权;粘贴可疑短信做风险话术核验。
- **家属端** `/family/` — 查看老人的出行确认状态、回复老人的联系请求、查看**已授权**的共享事项、只读查看授权范围、查看协同记录。**不能替老人确认**——出行方式只能由老人本人在老人端确认。
- **社区端** `/community/` — 按风险/时限处理协同队列、承接事项、查看 8 位值班人员的资源与负荷、配置调度规则。可在左下角切换"当前登录的服务人员",每个人的工作台与待办是独立的。

## 数据与存储键

所有状态都在 `localStorage`。键名集中定义在 `shared.js` 的 `KEYS` 里:

| 键 | 内容 | 谁写 | 谁读 |
| --- | --- | --- | --- |
| `yilian-events` | 老人的生活事项 | 老人端 | 老人端、家属端(按授权过滤) |
| `yilian-contact-requests` | 老人发出的联系请求与回复 | 老人端(发起)、家属端(回复) | 老人端、家属端 |
| `yilian-permissions` | 共享授权四个开关 | 老人端 | 老人端、家属端 |
| `yilian-escort` | 「确认社区陪诊」的状态 | 老人端 | **三端共读** |
| `yilian-community-queue` | 社区协同队列(含承接结果) | 社区端 | 社区端 |
| `yilian-community-rules` | 调度规则开关 | 社区端 | 社区端 |
| `yilian-large-text` | 大字模式 | 三端 | 三端 |
| `ylCommunityStaff` | 社区端当前登录人员 | 社区端 | 社区端 |

页面之间靠 `storage` 事件同步(该事件只在**其他**标签页触发,所以单开一个标签页时看不到"另一边"的变化)。

### 三端是怎么串起来的

1. **复诊出行确认(主线)** — 老人端点「确认社区陪诊」→ 写入 `yilian-escort` → 家属端的"需要协助"从 1 变 0、卡片状态变成"老人已确认"、协同记录新增一条;社区端队列里 `周淑兰 · 确认陪诊安排` 的状态跟着变成"老人已确认"。
2. **联系消息** — 老人端发起联系请求 → 家属端"待回复"计数 +1 并可回复 → 老人端出现通知角标与对话记录。
3. **共享授权** — 老人端关掉某一项后,家属端"共享事项"里对应类型的事项立即消失;家属端始终只读。

## 资源与缓存

静态资源统一带一个版本号,四个 HTML 里的值**必须保持一致**:

```html
<link rel="stylesheet" href="../role.css?v=8"/>
<script src="../seed.js?v=8"></script>
```

**改动任意 `.css` / `.js` 后,请把所有 `?v=8` 一起改成 `?v=9`(再下次改 v=10),否则浏览器可能继续用缓存里的旧文件。** 项目没有构建步骤;如果后续接入了打包工具,这一步可以交给工具生成内容哈希。

## 样式结构:`role.css` 的 @layer

这个文件是历史上几次视觉迭代**叠加**出来的(初版 → 2026 视觉系统 → 玻璃拟态层 → 社区人员切换器)。原先"谁生效"取决于规则在文件里出现的先后顺序,很难维护;现在改为显式分层:

```css
@layer base, system2026, glass, staff, a11y, fixes;
```

- `base` 初版结构(栅格、组件骨架、基础排版)
- `system2026` 2026 视觉系统(配色、圆角、动效基调)
- `glass` 玻璃拟态表面层
- `staff` 社区端"当前登录人员"切换器
- `a11y` 无障碍与低端设备性能,以及本轮新增的界面元素
- `fixes` **例外层**:少数必须压过后面图层的高优先级规则,每条都写了原因

**新增样式请加进 `a11y`;确实需要压过 `a11y`/`glass` 时再加进 `fixes` 并写明原因。** 分层之后,层与层之间的优先级由上面这行声明决定,同层内才看选择器权重和先后顺序——注意这与"不看分层、纯按权重"的直觉不同,`fixes` 里那几条例外正是为此存在。

字号统一用 `rem` 表达,所以「大字模式」只是把 `<html>` 的字号放大到 118%,整页文字随之变大(`html.large-text`)。

## 无障碍与低端设备

- **移动端抽屉**:≤800px 时侧边栏是抽屉。收起时通过 `inert` 移出 Tab 序与可访问性树(不支持 `inert` 的旧浏览器回退到 `visibility:hidden`);打开时焦点自动进入抽屉第一项,关闭(Esc / 点遮罩)后焦点回到菜单按钮。
- **导航语义**:当前栏目写入 `aria-current="page"`;视图切换会同步到地址栏 hash,可深链、可后退。
- **大字模式**:见上,按钮同时带 `aria-pressed`。
- **低端设备**:≤590px 会关闭大面积 `backdrop-filter` 与 `background-attachment:fixed`,并隐藏两个固定的模糊装饰圆点,避免老人机上滚动掉帧(玻璃质感会弱一些)。
- 已处理 `prefers-reduced-motion`。

## 可选的智能体工具(WebMCP)

页面在浏览器支持 [WebMCP](https://github.com/webmachinelearning/webmcp) 时(via `navigator.modelContext.registerTool`)会暴露若干工具,例如老人端的"查看我的生活事项""确认社区陪诊"、家属端的"回复老人消息"。**不支持时静默跳过**,不影响页面本身的使用。

## 已知的简化之处

- 「确认社区陪诊」等状态没有时间维度的日程模型,`明天上午 09:30` 是文案而非真实日程。
- 社区端的服务负荷按"名下事项数 / 能力上限"实时估算,不是真实排班系统。
- 事项与人员的数量都是演示用的样本规模(16 条队列、8 位值班人员)。
- 安全核验用四条正则规则匹配风险话术,只是交互示意,不是风控能力。
